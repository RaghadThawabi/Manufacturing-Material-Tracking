MaterialFlow: complete pilot guide

Core phases 1–5 · Feature inventory, permissions, publishing and acceptance scenarios

Use a dedicated Pilot Test company, not live factory records. These scenarios are a repeatable acceptance checklist—not a claim that every case below has already been browser-tested. Publishing and real-account login must be verified on your published URL.

1. Publish for employee testing

  1. Open Replit’s Publishing tool / Publish button. Review build, database and access settings.
  2. For straightforward employee testing choose Public app access if your workspace permits it. This removes the Replit deployment-access gate; MaterialFlow still requires sign-in and company membership for company data. The anonymous sample demo remains public. If company policy requires Invite only, authorize each tester at the Replit publishing-access layer and through MaterialFlow Team. These are separate permissions.
  3. Review the production database choice. Development and production are separate. If the initial-publish option Set up your production database with your current development data is offered, select it only if you intentionally want those records copied. Otherwise create the Pilot Test company after publishing. Do not overwrite an existing production database merely to test.
  4. Click Publish and wait for completion. Copy the actual published URL shown by Replit. Do not use a .replit.dev preview link for employees.
  5. Open the published URL as Admin. Confirm company records are present if you chose to copy them. Otherwise create a test company. Check the name, role and account shown before proceeding.
  6. From Settings → Team on the published app, create/copy each invitation. Invitations copied from development point to development and may reference records absent from production. Share the links manually; automatic email delivery is not provided.
  7. Use separate browser profiles or devices for Admin, Manager, Supervisor, Operator A and Operator B. Each must sign in with a distinct account. Incognito windows within the same browser can share a session, so profiles are safer.
  8. Employees open their invitation, sign in using the existing Replit sign-in flow, and join the company. For email-bound invitations use the matching account email. Check the resulting company and role. An invitation does not switch the currently signed-in account.

If you see Replit’s “You don’t have access to this app,” check the URL and deployment sharing first. That is outside MaterialFlow’s role controls. Do not grant employees project Editor access just to use the app; project collaborators can access code and project history.

6. Sign-off before advanced features

Record each scenario as Pass / Fail / Not tested, account role, job number, date and observed result. Fix failures before using real production records. Keep Pilot Test separate; historical records are not disposable demo data. Confirm real published-account invitations, company isolation, balance enforcement, review, rework and CSV accuracy before starting an advanced feature.

Suggested next capability after acceptance: corrective-action tracking linked to recorded scrap issues, responsible staff, evidence and subsequent approved results—without claiming causation merely from a before/after change.
